What this shows
---------------
The protection is FORMAT PRESERVING and REVERSIBLE, which is the property AEGIS
is built on and the reason masking is not a substitute:

  123-45-6789            -> 616-16-2210              still a valid SSN shape
  jane.smith@example.com -> ASdT.Q6znF@example.com   still a valid address shape
  Jane Smith             -> mG5v fWZRf               still a plausible name

Every downstream consumer that validates format keeps working. Nothing
downstream ever receives a real person. And find_and_unprotect returns the exact
original for a caller entitled to it, which masking can never do.

Reproducing this
----------------
    cp .env.example .env          # add DEV_EDITION_EMAIL / _PASSWORD / _API_KEY
    cd data-discovery && docker compose up -d
    python protegrity_showcase.py

Stage 2 is skipped with a printed explanation when credentials are absent, and
protegrity_showcase.py asserts `protected != SAMPLE`, so a quota-exhausted or
unauthenticated run fails loudly here rather than silently reporting success.
That assertion is what caught the 403 in the first place.
